# Project notes

**What this is:** PNG LPV Election Simulator 2027 — Next.js app simulating ward-by-ward Limited Preferential Voting across all 89 PNG Open electorates.

**Auth:** Full multi-user auth (registration, email verification, login, logout, forgot/reset password). The gate is `src/proxy.ts` (Next 16 renamed `middleware`→`proxy`) which validates a stateless HMAC session cookie (`src/lib/session.ts`, Edge/Web-Crypto). Route handlers live under `src/app/api/auth/*` (`runtime="nodejs"`); pages are `src/app/{login,register,forgot-password,reset-password,verify-email}`. Users are stored in **SQLite** via `src/lib/db.ts` (`better-sqlite3`); passwords are scrypt-hashed (`src/lib/password.ts`); emails go through **Brevo** (transactional REST API via fetch in `src/lib/email.ts`, falls back to logging the link if `BREVO_API_KEY` is unset). Env vars (see `.env.example`): `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` (bootstrap admin, seeded on first run), `DATABASE_PATH`, `BREVO_API_KEY`, `EMAIL_FROM` (a Brevo-verified sender), `APP_URL`. Never hardcode secrets. Keep `DATABASE_PATH` (and `WARD_OVERRIDES_PATH`) OUTSIDE the app dir in prod (`/var/www/lpvpng-data/`) so `git pull` + rebuild never wipes the user DB. Generate an admin hash with `node scripts/hash-password.js "pass"`.

**Maps/boundaries:** District boundary GeoJSON (~14MB, one file per electorate) lives in `public/boundaries/<slug>.json` and is fetched client-side on demand — NOT bundled. `src/data/maps/boundary-index.json` (generated by `scripts/generate-boundary-index.mjs`) holds each district's center + zoom; `src/data/maps/registry.ts` builds a map config for every indexed electorate. The Voter Distribution map (`src/components/voter-distribution/`) lets users drag ward pins (saved to localStorage); admins can persist positions server-side via `POST /api/save-coordinates` (admin-gated) into `wardOverrides.json`.

**Data is JSON-driven, not CSV:** Electorates, LLGs, and wards live in `src/data/electorates.json` and `src/data/llgs/<province>.json`. The CSV files under `src/data/electoral-rolls/` are raw reference exports — they are NOT loaded at runtime, so adding wards only requires editing the JSON.

**Adding a new LLG:** Add an entry to the appropriate `src/data/llgs/<province>.json` under the matching `electorateSlug`. Each ward needs `id`, `name`, and `registeredVoters`. ID convention: `<electorate-slug>-<llg-slug>-<ward-num>---<ward-name-kebab>`. After adding, update `totalRegisteredVoters` for the electorate in `src/data/electorates.json`.

**Deployment:** Production is a DigitalOcean droplet (`134.199.169.242`, not App Platform). This merged app serves **smartvoterpng.com** (smartelectorates.com 301-redirects to it). Runs under PM2 as process `lpvpng` from `/var/www/lpvpng`. Deploy: SSH in, `git pull origin main`, `npm ci` (rebuilds the `better-sqlite3` native addon — required, don't skip), `npx next build`, `pm2 restart lpvpng --update-env`. The persistent user DB + saved ward coords live in `/var/www/lpvpng-data/` (set via `DATABASE_PATH`/`WARD_OVERRIDES_PATH`), outside the rebuilt tree. The droplet has uncommitted local-only modifications to `next.config.ts` (TypeScript ignoreBuildErrors) and `package.json` (`@types/pako`) — preserve these on pull.

**Branding:** Three-color PNG flag scheme — `png-red` (#CE1126), `png-gold` (#FCD116), `png-black` (#000000). The favicon (`src/app/icon.svg`) is the same tricolor.
